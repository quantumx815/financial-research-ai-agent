# Financial Research AI Agent

## Overview

Financial Research AI Agent is an AI-powered system designed to research and analyze publicly traded companies using financial data, recent news, official SEC filings, and AI-generated insights.

The system combines information from multiple sources and uses Retrieval-Augmented Generation (RAG) to provide more evidence-supported financial research through a user-friendly web interface.

## Objectives

* Collect company and financial information
* Retrieve relevant and recent financial news
* Access official SEC financial filings
* Process and retrieve relevant financial document information
* Generate structured, evidence-supported financial analysis using AI
* Present research results clearly through the frontend

## This Week's Development

### RAG and SEC Financial Document Integration

The main focus this week was improving the reliability and evidence quality of the financial research generated by the system.

### 1. SEC Financial Document Integration

Official SEC EDGAR filings were integrated as a trusted source of financial information.

The system can identify and retrieve relevant company filings, such as **Form 10-Q**, which provides primary-source financial information directly from the company filing records.

### 2. Financial Document Processing

Retrieved SEC documents are processed before being used by the AI system.

The processing pipeline includes:

```text
SEC Filing
    ↓
Document Retrieval
    ↓
Text Extraction
    ↓
Document Cleaning
    ↓
Chunking
    ↓
Embedding Generation
    ↓
Vector Storage
```

This allows large financial documents to be divided into smaller meaningful sections that can be searched efficiently.

### 3. Embedding and Vector Database

The processed document chunks are converted into vector embeddings using the Gemini embedding model.

These embeddings are stored in **ChromaDB**, which acts as the project's local vector database.

This enables the system to search financial documents based on **meaning and relevance**, rather than only matching exact keywords.

### 4. Retrieval-Augmented Generation

The RAG workflow was integrated into the company research process.

When a company is analyzed, the system retrieves relevant sections from the stored SEC financial documents and provides that evidence to Gemini along with the existing financial and news information.

```text
Company Search
     ↓
Financial Data + News
     ↓
Relevant SEC Evidence
     ↓
RAG Retrieval
     ↓
Gemini Analysis
     ↓
Evidence-Supported Research
```

This improves the ability of the AI to support its financial insights with information from official filings.

### 5. Gemini Analysis Enhancement

The Gemini analysis workflow was updated to use the retrieved SEC evidence.

The generated research now includes structured sections such as:

* Company Overview
* Financial Health
* Recent News
* Potential Positive Factors
* Potential Risks
* Overall Research Perspective

SEC evidence can also contribute directly to the reasoning behind financial risks and other research findings.

### 6. Frontend Integration and Testing

The complete RAG workflow was connected to the existing frontend and tested end-to-end.

The test confirmed that:

* Company data is retrieved successfully
* Financial information is displayed
* Recent news is displayed
* SEC evidence reaches the AI analysis
* Gemini generates the RAG-enhanced research
* Risks and opportunities are displayed correctly
* The final structured analysis is visible in the frontend

**Current milestone: RAG integration and frontend end-to-end testing completed successfully.**

### Backend

The `Backend` directory contains the main research and AI processing logic.

* **`main.py`** — Starts the FastAPI application.
* **`routes/company.py`** — Handles company research requests and connects the different research services.
* **`financial_data.py`** — Retrieves company and financial information.
* **`news_service.py`** — Retrieves and processes recent company-related news.
* **`gemini_service.py`** — Sends research context to Gemini and generates the structured analysis.
* **`embedding_service.py`** — Generates vector embeddings for financial document chunks.
* **`rag_service.py`** — Handles vector storage and relevant document retrieval using ChromaDB.
* **`sec_service.py`** — Communicates with SEC EDGAR to identify and retrieve official company filings.
* **`document_service.py`** — Handles financial document retrieval and management.
* **`document_processor.py`** — Processes documents and divides them into useful text chunks.
* **`ingestion_service.py`** — Connects document processing, embedding generation, and ChromaDB ingestion.

### Data

The `Data` directory contains the project's financial document and vector database storage.

* **`raw/`** — Stores retrieved financial documents before processing.
* **`processed/`** — Stores cleaned and structured document data ready for ingestion.
* **`chroma/`** — Contains the persistent ChromaDB vector database.

### Frontend

The `frontend` directory contains the web interface through which users search for companies and view the generated research analysis.

The frontend communicates with the FastAPI backend and displays the structured AI-generated results.

### Tests

The `Backend/tests` directory contains automated tests for:

* Company API functionality
* Gemini analysis
* RAG services
* Complete RAG integration

### Documentation

The `docs` directory contains project documentation and the RAG architecture description.
